# WP PinFeed (`wp-pinfeed`)

Версия 0.3.0 · WordPress-плагин, который отдаёт RSS-ленты для автопубликации в Pinterest.
Ленты собираются по таксономиям, текст пина строится по шаблонам (и при желании пишется
моделью). Картинка пина берётся из записи — готовый пин github-repos, изображение записи,
первое изображение в тексте; если подходящего нет — плагин генерирует **вертикальную
инфографику 2:3** (заголовок и нумерованные тезисы, которые пишет модель). Самодостаточен — без ACF/CPT UI, переносится
на любой сайт сети копированием папки. Работает в связке с
[`llm-agent-articles`](https://github.com/Geliorn/llm-agent-articles) и
[`llm-agent-github-repos`](https://github.com/Geliorn/llm-agent-github-repos), но не зависит от них.

## Как Pinterest работает с RSS

Pinterest → Settings → **Bulk create Pins** → **Auto-publish** → *Connect RSS feed*:
указывается URL ленты и **одна доска**. Pinterest забирает ленту примерно раз в сутки и
создаёт пины из новых `<item>` (до 200 пинов в день на аккаунт). Из уже созданного пина
он больше ничего не перечитывает — ни текст, ни картинку. Отсюда два правила плагина:

- `<guid>` элемента стабилен (`/?p=ID`) и не зависит от шаблонов и UTM — правка ленты
  не превращает старые записи в «новые»;
- элемент лучше отдавать уже с готовой картинкой (см. «Пока пин не собран»).

## Два вида лент

**Ленты из админки** (`Pinterest → Добавить ленту`, тип записи `pinfeed`). У каждой —
свой адрес `https://site/pinfeed/<слаг-ленты>/` и полный набор настроек ниже. Одна
лента может объединять несколько типов записей, например статьи и репозитории по MCP.

**Автоленты терминов** (`Pinterest → Автоленты`). Отмечаете таксономии — у каждого их
термина появляется лента `https://site/pinfeed/term/<таксономия>/<слаг-термина>/`.
Все автоленты настраиваются одним набором (та же форма); условие «запись в этом
термине» добавляется само. Адрес автоленты виден на экране редактирования термина.
Термины, где записей меньше заданного минимума, отдают 404.

Без ЧПУ работают и адреса-параметры: `/?wppf_feed=<слаг>`,
`/?wppf_tax=<таксономия>&wppf_term=<слаг>`. Добавьте `?wppf_preview=1` к адресу
ленты — редактор увидит HTML-сетку пинов с длиной текстов, источником картинки и
статусом каждого элемента (посетителю без прав отдаётся обычный XML).

## Настройки ленты

### Что попадает

| Поле | Что делает |
|---|---|
| Типы записей | Любые публичные: `post`, `github_repo`, … |
| Условия по таксономиям | Строки «таксономия + условие + термины»: *любой из* (IN), *ни один из* (NOT IN), *все сразу* (AND), *есть любой термин*, *нет терминов*; флажок «с дочерними». Связь между строками — И / ИЛИ. Термины — **слаги** через запятую (переносимо между сайтами), числа считаются ID |
| Сортировка | По дате, по обновлению, случайно, по числовому мета-полю (например `_gh_stars`), по комментариям |
| Записей в ленте | По умолчанию 25 |
| Не старше, дней / задержка, минут | Окно по дате публикации. Задержка даёт время проставиться обложке, SEO-полям и фоновой генерации |
| Исключить ID | Плюс флажок «Не публиковать в Pinterest» у любой записи. Запись без картинки в ленту не попадает никогда — Pinterest без картинки пин не создаст |

### Текст пина — шаблоны

| Подстановка | Значение |
|---|---|
| `{title}` | Заголовок записи |
| `{excerpt}` | Отрывок или первые 55 слов текста |
| `{content:300}` | Текст записи до N символов |
| `{short_description}` | Краткое описание репозитория (`llm-agent-github-repos`) |
| `{seo_title}` `{seo_description}` | Из Yoast / Rank Math (определяется автоматически) |
| `{pin_title}` `{pin_description}` | Ручной текст из метабокса «Pinterest» у записи |
| `{llm_title}` `{llm_description}` | Текст от модели (см. ниже) |
| `{terms:category:3}` `{term:repo_topic}` | Термины через запятую / первый термин |
| `{hashtags:post_tag:5}` | Хэштеги из терминов: «AI агенты» → `#AIАгенты`. `*` вместо таксономии — все |
| `{meta:ключ}` | Любое мета-поле |
| `{date}` `{author}` `{post_type_label}` `{permalink}` | |
| `{feed_title}` `{feed_slug}` `{term_name}` `{term_slug}` | Лента / термин автоленты |
| `{site_name}` `{site_domain}` `{site_url}` | |
| `{gh_stars}` `{gh_forks}` `{gh_language}` `{gh_license}` `{gh_full_name}` `{gh_url}` | Если стоит `llm-agent-github-repos`. `{gh_stars}` → «★ 15,2k» |
| `{primary_keyword}` | Главный ключ статьи `llm-agent-articles` |

`{a|b|c}` — первое непустое значение, `{excerpt|"Читать на сайте"}` — текст в кавычках
как последний вариант. Неизвестная подстановка даёт пустую строку (и проваливается
дальше по цепочке) — опечатка не утечёт в публичный пин.

По умолчанию заголовок — `{pin_title|llm_title|seo_title|title}`, описание —
`{pin_description|llm_description|seo_description|short_description|excerpt|content:400}`
плюс строка хэштегов. Пределы Pinterest (100 / 500 символов) соблюдаются обрезкой по
границе слова; хвостовая строка хэштегов при обрезке сохраняется целиком.

### Текст от модели (LLM)

Включается в ленте. Модель получает заголовок, описание, термины, начало текста и тему
доски и возвращает JSON `{title, description}` — подставляется в `{llm_title}` и
`{llm_description}`. Дополнительно: язык, ключевые слова доски (можно шаблоном,
например `{primary_keyword}`), свободные требования.

- **Никогда не вызывается, пока Pinterest ждёт ленту.** Тексты пишет фоновая задача;
  до готовности цепочка шаблона берёт следующий вариант (`{seo_description}`, …).
- Ответ кэшируется в мете записи `_wppf_llm` с ключом по настройкам промпта и временем
  правки записи — правка записи или промпта сама делает его устаревшим.
- Запись, на которой модель ошиблась, откладывается на 6 часов, чтобы не съедать бюджет.
- Провайдеры те же, что в соседних плагинах: Yandex Foundation Models, DeepSeek, Qwen,
  Timeweb TWC AI, OpenRouter. Ключи свои, но в `Настройки` есть кнопка «Скопировать
  провайдера и ключи» из `llm-agent-articles` или `llm-agent-github-repos`.

### Картинка пина

Раздел «Картинка пина» в ленте — три шага сверху вниз:

**1. Источники изображения** — список с флажками, порядок меняется перетаскиванием,
берётся первое найденное изображение:

| Источник | Откуда |
|---|---|
| Изображение из блока «Pinterest» записи | поле в метабоксе «Pinterest» на экране редактирования записи (его добавляет этот плагин). Выбрано вручную — берётся всегда, даже горизонтальное |
| Готовый пин из плагина «GitHub-репозитории» | `_gh_pin_image_id` — картинка 1000×1500, которую `llm-agent-github-repos` собирает специально для Pinterest (на сайте не выводится). Пункт виден, только если плагин установлен |
| Изображение записи (миниатюра) | featured image; у статей `llm-agent-articles` — обложка или инфографика статьи |
| Первое изображение в тексте записи | первая картинка в содержимом |
| Мета-поле записи | произвольное поле с ID вложения или URL; ключ вводится в самом пункте |

**2. Горизонтальные изображения** (шире, чем высота): *пропускать* (по умолчанию) —
тогда проверяется следующий источник, а если ничего не осталось — шаг 3; или *брать
как есть*.

**3. Если изображения нет**: *сгенерировать инфографику* (по умолчанию) или *не включать
запись в ленту*.

Пропущенное горизонтальное изображение может стать фоном инфографики (пресет с фоном
«Картинка записи, затемнённая»).

#### Инфографика

Как инфографика статей в `llm-agent-articles`, только вертикальная 1000×1500: акцентная
полоса, заголовок (`{pin_title|llm_title|title}`), 3–8 тезисов (по умолчанию 5) —
нумерованным **списком** или **сеткой** блоков, у тезиса короткая метка и одно
предложение, внизу подпись (`{site_domain}`) и логотип. Все тезисы набираются одним
кеглем (метки — жирным, текст — обычным начертанием, если рядом со шрифтом есть
regular-версия).

**Откуда тезисы:**

1. вручную — поле «Тезисы для инфографики» в блоке «Pinterest» записи (по строке,
   `Метка: текст` или просто текст);
2. иначе их пишет **модель** по заголовку, описанию и тексту записи; предел длины
   тезиса считается из пресета. Только в фоновой задаче, с кэшем в мете `_wppf_theses`.
   Структура записи («Коротко», заголовки H2, списки) передаётся модели как контекст,
   но тезисами сама не становится — без модели качественной инфографики не получится.

**Без тезисов пина нет.** Пока модель не ответила, если ключи не заполнены, модель
ответила ошибкой (повтор через 6 часов, причина — в журнале) или в записи меньше 300
символов текста — запись в ленту не попадает. Причину видно в предпросмотре ленты.

**Текст не обрезается никогда.** Тезис, который не влезает в свой блок, фоновая
задача просит модель переписать короче под измеренный бюджет символов; что всё равно
не влезло — убирается при сборке целым пунктом (самый длинный первым), но не меньше трёх.

**Пресеты** (`Pinterest → Пресеты картинок`) — с живым предпросмотром на реальной записи
(её тезисы или пример): размер, поля, фон (цвет / затемнённая картинка записи), градиент,
акцентная полоса, заголовок (кегль с автоподбором, строки, выравнивание), раскладка
список/сетка и число колонок, плашки пунктов, маркер (номер в круге / квадрате / без
подложки / точка / без маркера), метка, кегль текста и его минимум, подпись, логотип.
Стартовые: «Тёмный список», «Сетка 2 колонки», «Светлый список». Экспорт/импорт JSON.

Сгенерированные пины — обычные файлы в `uploads/wppf-pins/<ID записи>/`, не вложения
медиатеки. Имя файла содержит хэш всего, что влияет на картинку (пресет, заголовок,
тезисы, подпись, фон), поэтому изменения подхватываются сами, а неизменённый пин
сохраняет стабильный URL. Старые версии удаляются при сборке новой и при удалении записи.

При запросе ленты синхронно собирается не больше N пинов (настройка, по умолчанию 3) и
ничего не скачивается из сети; остальное доделывает фоновая задача. Несобранный пин
в ленту не попадает — Pinterest создаёт пин один раз и картинку потом не перечитывает.

**Шрифт.** GD нужен TTF/OTF: шрифт пресета → путь из настроек → загруженные
(`uploads/wppf-fonts/`, а также `uploads/laa-fonts/` от `llm-agent-articles`) →
системные (DejaVu, Noto, Liberation).

### Ссылка

UTM-метки (`utm_source=pinterest`, `utm_medium=social`, `utm_campaign={feed_slug}`) —
с подстановками, отключаются флажком.

## Готовые профили

В форме ленты (и автолент) — «Быстрый старт», появляется, если на сайте есть
соответствующий плагин:

- **Статьи блога (llm-agent-articles)** — `post`, SEO-описание → отрывок, хэштеги из меток;
  картинка: блок «Pinterest» → изображение записи → первое изображение в тексте,
  горизонтальные берутся как есть (обложки и инфографика статей — 3:2); если картинки
  нет — инфографика «Тёмный список»; задержка 30 минут (статья публикуется раньше, чем
  к ней прикрепляется обложка).
- **GitHub-репозитории (llm-agent-github-repos)** — `github_repo`; описание —
  `{gh_pin_description}` (его пишет github-repos вместе со своим пином), иначе
  `short_description`; строка «★ звёзды · язык», хэштеги из `repo_topic` и меток;
  картинка: блок «Pinterest» → **готовый пин github-repos** → изображение записи;
  если нет — инфографика «Сетка 2 колонки» с тезисами от модели. Аватар владельца
  (`_gh_owner_avatar`) — часть дизайна сайта, в ленте не используется.

Профили расширяются фильтром `wppf_profiles`.

## Фоновая задача

Как в соседних плагинах — три равноправных триггера одного тика:

1. WP-Cron раз в 10 минут (по умолчанию);
2. HTTP-эндпоинт за секретом: `curl "https://site/?pinfeed_cron=СЕКРЕТ"` (троттлинг раз в минуту);
3. прямой PHP CLI: `php wp-content/plugins/wp-pinfeed/cron.php`.

Готовые строки для crontab — в настройках. Тик проходит по всем включённым лентам и по
автолентам, которые Pinterest забирал за последние 14 дней (терминов на сайте могут быть
тысячи — греются только реально подключённые), просит у модели тезисы и тексты и
собирает пины в пределах бюджетов «запросов к модели за тик» и «пинов за тик».

## Кэш

XML ленты кэшируется (по умолчанию 30 минут). Сохранение любой записи или смена
терминов сбрасывает кэш всех лент; лента, в которой ещё есть несобранные пины, не
кэшируется вовсе — следующий запрос получит готовые.

## WP-CLI

```
wp pinfeed list
wp pinfeed warm                         # тик сейчас
wp pinfeed preview <ID> [--render]      # что отдаст лента
wp pinfeed preview post_tag:mcp         # автолента термина
wp pinfeed xml <ID> > feed.xml
wp pinfeed import-llm --from=articles   # или github_repos
wp pinfeed flush-cache
```

## Хуки

| Хук | Назначение |
|---|---|
| `wppf_query_args` (filter) | Последнее слово о `WP_Query` ленты |
| `wppf_placeholder` (filter) | Свои подстановки: вернуть строку для своего имени |
| `wppf_image_sources` / `wppf_image_source` (filter) | Свой источник картинки: зарегистрировать (`key => array( 'label', 'help' )`) / вернуть |
| `wppf_pin` (filter) | Последнее слово об одном пине (текст, ссылка, картинка, статус) |
| `wppf_profiles` (filter) | Свои профили быстрого старта |
| `wppf_metabox_post_types` (filter) | Типы записей с метабоксом «Pinterest» |

## Данные плагина

- CPT `pinfeed` — ленты (непубличный), мета `_wppf_*`.
- Опции `wppf_settings`, `wppf_auto_feed`, `wppf_infographic_presets`, `wppf_log`,
  `wppf_cache_ver`, `wppf_last_tick`, `wppf_rewrite_ver`.
- Мета записей: `_wppf_image_id`, `_wppf_pin_title`, `_wppf_pin_description`,
  `_wppf_theses_manual`, `_wppf_exclude`, `_wppf_llm`, `_wppf_theses`. Мета терминов:
  `wppf_last_fetch_at` (когда Pinterest забирал автоленту термина).
- Файлы: `uploads/wppf-pins/`, `uploads/wppf-fonts/`, журнал `uploads/wppf-pinfeed.log`.

Удаление плагина стирает всё перечисленное (и данные прежних версий: опцию
`wppf_image_presets`, мету терминов `wppf_image_id`). Пины, уже созданные в Pinterest, не
затрагиваются — Pinterest хранит свою копию картинки.

## Требования

- WordPress 6.0+, PHP 7.4+ (проверено на 8.3).
- GD с FreeType — для генерации инфографики (без него в ленту попадают только записи
  с готовым изображением).
- Ключи одной из моделей — для тезисов инфографики (и, если включено, текста пина).

## Безопасность

Нонсы на всех формах и AJAX, `manage_options` на настройках, пресетах и автолентах,
`edit_post` на ленте и метабоксах. HTML-предпросмотр ленты — только для `edit_posts`.
HTTP-триггер — по секрету (`hash_equals`) с троттлингом. Загружаемый шрифт проверяется
по сигнатуре файла. Ответ модели и все тексты проходят очистку от HTML; в XML запрещённые
управляющие символы вырезаются, чтобы случайный символ из README не ломал всю ленту.
